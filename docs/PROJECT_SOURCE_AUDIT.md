## Editorial rules

1. Original years are historical facts; new extensions get their real date.
2. Distinguish input, feature plans, build checks, end-to-end tests, and visual prototype outputs.
3. Never label an unavailable executable as playable or an uninspected source package as tested.
4. Group work must retain its collective attribution.
5. Never publish credentials, CV addresses/phone numbers, private IDs or unreviewed course submissions.
6. Prefer verifiable screenshot/code/demo evidence over technical output trivia.
